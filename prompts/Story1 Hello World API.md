# Story 1: Hello World API Specification

## Overview
A simple Spring Boot API that returns "Hello World" via a GET request. This application is designed to run in an AWS Elastic Beanstalk (EB) environment on Java 25.

## Technical Stack
- **Platform:** Java 25
- **Build Requirement:** Gradle must use a Java 25 toolchain. If Java 25 is unavailable, the build must fail clearly rather than falling back to another Java version.
- **Framework:** Spring Boot 4.0.6 (Latest stable as of May 2026)
- **Build Tool:** Gradle
- **Dependencies:** 
    - `spring-boot-starter-web`: For REST API support.
    - `spring-boot-starter-actuator`: For health checks and monitoring.

## Endpoints

### 1. Hello World
- **URL:** `/hello`
- **Method:** `GET`
- **Response Type:** `text/plain`
- **Response Body:** `Hello World`
- **Status Code:** `200 OK`

### 2. Health Check (Elastic Beanstalk Standard)
AWS Elastic Beanstalk uses health checks to determine if the application is running correctly.

#### Root Health Check (Default EB)
- **URL:** `/`
- **Method:** `GET`
- Response Type: `text/plain`
- Response Body: ```OK```
- **Status Code:** `200 OK`
- **Note:** EB default health check path is often `/`. We will map this to a simple status check.

#### Actuator Health Check (Standard Spring Boot)
- **URL:** `/actuator/health`
- **Method:** `GET`
- Response Type: `application/json`
- **Response Body:** `{"status": "UP"}`
- **Status Code:** `200 OK`

#### Health Alias for EB
- **URL:** `/health`
- **Method:** `GET`
- **Description:** A common alias used in EB configurations.
- Response Type: `application/json`
- Response Body: `{"status":"UP"}`
- **Status Code:** `200 OK`

## Configuration

### Server Port 
AWS Elastic Beanstalk (AL2/AL2023) environments expect the application to listen on port `5000` and will proxy from port 80 to `5000`.
For simplicity and following EB best practices for Java SE platforms, we will configure the app to listen on port `5000`.
The app should listen on the port provided by the `PORT` environment variable, defaulting to `5000` locally.

**application.properties:**
```properties
server.port=${PORT:5000}
management.endpoints.web.exposure.include=health
```

## Build and Deployment

### Gradle Configuration
The build should be configured to produce a self-contained, executable JAR file suitable for deployment to AWS Elastic Beanstalk.

- **Task:** `bootJar`
- **Output:** An executable JAR file (e.g., `build/libs/agilenoir-api-1.0.0.jar`).
- **Elastic Beanstalk Compatibility:** The JAR must include all dependencies and be runnable via `java -jar <filename>.jar`.

### Deployment Artifact
For Elastic Beanstalk (Java SE Platform), the primary deployment artifact is the executable JAR file generated by the Gradle `bootJar` task.

- The project builds successfully with Gradle.
- The project includes a `bootJar` task that produces a self-contained JAR file.
- `GET /hello` returns:
  - Status: `200 OK`
  - Content-Type: `text/plain`
  - Body: `Hello World`
- `GET /` returns:
  - Status: `200 OK`
  - Content-Type: `text/plain`
  - Body: `OK`
- `GET /health` returns:
  - Status: `200 OK`
  - JSON Body containing: `"status": "UP"`
- `GET /actuator/health` returns:
  - Status: `200 OK`
  - JSON body containing `"status":"UP"`
- Automated tests cover `/hello`, `/`, `/health`, and `/actuator/health`.
- `./gradlew test` passes.
- `./gradlew bootJar` creates an executable JAR deployable to AWS Elastic Beanstalk.
